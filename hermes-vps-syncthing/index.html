Run Hermes from a VPS. Let Syncthing carry the memory.

A practical, battle-tested pattern for a personal AI agent: Hermes runs 24/7 on a cheap Linux server, talks through Telegram/Discord, and shares an Obsidian-style workspace through Syncthing without dumping your life into a cloud drive. Elegant? Mostly. Effective? Annoyingly so.

Architecture

The setup is three loops, not one monolith.

Keep the pieces boring. The clever part is letting each tool do one job: Hermes thinks and acts, Syncthing moves files, systemd keeps the lights on.

Personal machine

  • Obsidian / local notes
  • Optional Hermes CLI or desktop
  • Syncthing device ID paired with VPS
  • Human review before public sharing
Syncthing
trust pair

VPS agent box

  • Hermes Agent installed under one Linux user
  • Gateway service for Telegram/Discord/etc.
  • Cron jobs, skills, memory, logs
  • Synced workspace folders mounted locally
Loop 01

Conversation

Message the agent from your phone. The gateway maps chats to sessions and can stream edited replies on platforms like Telegram.

Loop 02

Filesystem

Syncthing syncs the working vault peer-to-peer. No Google Drive roulette, no mysterious conflict goblin if you respect folder ownership.

Loop 03

Automation

Hermes cron, skills, and memory let the VPS do periodic work while the laptop sleeps. The little bounty hunter does not require a MacBook battery.

Build path

From fresh VPS to working Hermes.

These commands assume Ubuntu/Debian and a non-root user named however you like. Replace paths and platform choices to match your actual box.

Harden the VPS before giving an agent hands.

Create an unprivileged user, use SSH keys, disable password login, and keep the firewall narrow. Hermes is useful precisely because it can act; do not hand it a glass cannon and call it infrastructure.

sudo apt update && sudo apt upgrade -y
sudo adduser hermes
sudo usermod -aG sudo hermes
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 22000/tcp
sudo ufw allow 22000/udp
sudo ufw enable

Install Hermes and prove the baseline works.

The official docs say: install, set a provider, then verify a normal chat before layering on gateway, cron, tools, or voice. This avoids debugging five things at once, the traditional sport of our people.

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.bashrc
hermes setup --portal   # fastest path, or use: hermes model
hermes doctor
hermes chat -q "Reply with the hostname and one setup warning."

Install Syncthing from the official apt repo.

Syncthing device IDs are public-key-style identifiers; the connection only works when both devices add each other. Keep the GUI bound to localhost and reach it with an SSH tunnel.

sudo mkdir -p /etc/apt/keyrings
sudo curl -L -o /etc/apt/keyrings/syncthing-archive-keyring.gpg \
  https://syncthing.net/release-key.gpg
echo "deb [signed-by=/etc/apt/keyrings/syncthing-archive-keyring.gpg] https://apt.syncthing.net/ syncthing stable-v2" \
  | sudo tee /etc/apt/sources.list.d/syncthing.list
printf "Package: *\nPin: origin apt.syncthing.net\nPin-Priority: 990\n" \
  | sudo tee /etc/apt/preferences.d/syncthing.pref
sudo apt update && sudo apt install syncthing -y

Run Syncthing as a user service.

User services are enough for a personal VPS. Enable linger so the service survives SSH logout. Then tunnel the GUI instead of opening port 8384 to the public internet.

sudo loginctl enable-linger "$USER"
systemctl --user enable --now syncthing.service
systemctl --user status syncthing.service --no-pager

# From your laptop:
ssh -L 8384:127.0.0.1:8384 your-vps
# Then open http://localhost:8384

Create the shared workspace folder intentionally.

For an Obsidian/Hermes workspace, share a folder like ~/obsidian-sync/Remote. On the laptop, decide whether the VPS is allowed to write. Our pattern: editable workspace folders, but clearly mark receive-only/archive areas when the server should not mutate them.

mkdir -p ~/obsidian-sync/Remote
mkdir -p ~/obsidian-sync/Remote/{Inbox,Journal,Working\ Files,Hermes}

# In the Syncthing GUI:
# 1. Actions → Show ID on both devices
# 2. Add Remote Device on both sides
# 3. Add Folder: path ~/obsidian-sync/Remote
# 4. Share folder with the other device
# 5. Pick folder type: Send & Receive, Send Only, or Receive Only

Add the messaging gateway last.

Once CLI chat works and the filesystem is healthy, configure Telegram/Discord/Slack/etc. The gateway is the always-on bridge between your phone and the VPS agent.

hermes gateway setup
hermes gateway install
hermes gateway start
hermes gateway status

# Useful recovery moves:
hermes logs gateway --tail 80
systemctl --user restart hermes-gateway
Tips & tricks

Lessons from running it for real.

These are the things that keep the setup from turning into a haunted filing cabinet with an API key.

Keep Syncthing’s GUI private.

Expose 22000 for sync traffic if needed, not 8384. Use ssh -L 8384:127.0.0.1:8384 vps for admin access.

Pair devices both ways.

Syncthing will not connect until each device trusts the other device ID. The ID is not a password; it is closer to a public key fingerprint.

Separate secrets from synced notes.

Hermes secrets belong in ~/.hermes/.env or an external secret provider, not in the Obsidian vault. Notes sync; keys stay local.

Do not give every folder to the agent.

Use receive-only or send-only modes for archives and sensitive material. The agent is loyal, not omniscient. Also, typos exist.

Name your operational notes.

Keep AGENTS.md, LANDMARKS.md, and workspace docs near the files Hermes edits. Context files beat “remembering” by vibes.

Use cron for exact schedules, heartbeat for batches.

Hermes cron is good for precise jobs and isolated runs. A heartbeat-style checklist is better for batching email/calendar/weather checks without spam.

Watch conflict files like smoke alarms.

Syncthing conflict files usually mean two devices edited the same note. Treat them as workflow feedback, not just clutter.

Verify after every layer.

Run hermes doctor, systemctl --user status, Syncthing folder health, and one real gateway message before declaring victory. The helmet stays on until extraction.

Readiness checklist

If these pass, you have an actual agent rig.

✓SSH: key-only login works; password and root SSH are disabled.
✓Firewall: only SSH and Syncthing traffic are public unless you intentionally added more.
✓Hermes: hermes doctor passes and a one-shot hermes chat -q returns cleanly.
✓Gateway: service starts on boot and can receive one real message from your chosen platform.
✓Syncthing: both devices show the folder as up to date and device IDs are mutually configured.
✓Vault policy: editable vs receive-only areas are clear before automation touches notes.
